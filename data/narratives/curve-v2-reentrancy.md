The Curve v2 incident of 30 July 2023 belongs to a family of exploits that all reduce to the same sentence: the protocol trusted a number it did not control. Here that number was the price of the collateral being liquidated, and the attacker controlled it for the length of a single transaction.

The public record puts the loss at roughly $69.3M in CRV and collateral. Our local reproduction rebuilds the mechanism rather than the incident: the same class of defect is executed against a deliberately vulnerable lending pool, so the trace can be read call by call instead of inferred from a block explorer. The recovered evidence shows the attacker re-entering the liquidation path while the pool was still reporting the pre-manipulation price, liquidating their own inflated position at an artificial profit. The detector classifies the sequence as Reentrancy with the same nesting signature that appears in the trace viewer: the same entry point invoked again, deeper, before the guarding state update completes.

The part worth carrying forward is the asymmetry. An investigator looking at a block explorer sees two ordinary transactions and a large transfer; an investigator looking at the trace sees one transaction in which a function is called seven times and the price is wrong on the last six. That difference — not the loss figure — is what turns an event into a case. The remediation follows the same shape as the exploit: the liquidation path must not read a price that the same transaction can move, and the state update that authorises a withdrawal must happen before the value leaves.
