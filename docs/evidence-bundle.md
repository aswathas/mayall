# Forensic Evidence Bundle Specification

Every investigation in `@helix/forensic-engine` produces a deterministic, self-contained ZIP archive (`<caseId>-forensic-bundle.zip`) built by [`packages/forensic-engine/src/bundle.ts`](../packages/forensic-engine/src/bundle.ts) (`buildForensicBundle`).

The bundle is designed so an external auditor, incident responder, or legal reviewer can verify every claim in the incident report against the raw execution output without trusting the web UI.

---

## 1. Archive Layout (12 Files)

Every generated forensic bundle contains the following files in a fixed order:

| # | Path in Archive | Category | Format | What It Contains & What It Proves |
| --- | --- | --- | --- | --- |
| 1 | `report/report.md` | `report` | Markdown (`UTF-8`) | Human-readable forensic report generated by `reportToMarkdown(report)`. Contains the executive summary, severity badge, key metrics, chronological attack sequence, root-cause narrative, affected contracts, storage slot mutations, balance deltas, detector findings, and remediation guidance. |
| 2 | `report/report.json` | `report` | JSON (`2-space indented`) | Machine-readable `ForensicReport` object produced by `buildReport()`. Proves the structured inputs that rendered `report/report.md`, including its own `sha256` digest over the canonical report payload. |
| 3 | `evidence/artifact.json` | `evidence` | JSON (`2-space indented`) | Complete `SimulationArtifact` emitted by the harness (`scenarioId`, `title`, `category`, `severity`, `summary`, `steps`, `balances`, `storageWrites`, `logs`, `metrics`, `narrative`). Proves the exact sequence of EVM calls, storage mutations, and balance snapshots captured during the simulation. |
| 4 | `evidence/trace.txt` | `evidence` | Plain text (`UTF-8`) | Verbatim `forge test -vvvv` call trace output (including `├─`, `└─`, `[gas]`, `[value: ...]`, `[delegatecall]`, `emit`, and `← [Revert]`). Proves the raw call hierarchy and frame gas budgets before any parser transformation. |
| 5 | `evidence/foundry-stdout.txt` | `evidence` | Plain text (`UTF-8`) | Raw `stdout` stream captured from the `forge test` child process (or an explicit empty-stream marker when loaded from pre-captured fixtures). Proves exact compiler/runner output. |
| 6 | `evidence/foundry-stderr.txt` | `evidence` | Plain text (`UTF-8`) | Raw `stderr` stream captured from the `forge test` child process. Proves whether any compiler warnings or runner diagnostics occurred. |
| 7 | `evidence/storage-diff.csv` | `evidence` | RFC 4180 CSV | Tabular export of every `SSTORE` (`stepIndex,contractLabel,contractAddress,slot,slotLabel,oldValue,newValue`). Allows spreadsheet or SQL auditing of state transitions. |
| 8 | `evidence/balance-timeline.csv` | `evidence` | RFC 4180 CSV | Tabular export of account balance checkpoints (`label,address,beforeWei,afterWei,deltaWei,deltaEth`). Proves conservation of value and exact net outflows/inflows. |
| 9 | `evidence/timeline.csv` | `evidence` | RFC 4180 CSV | Tabular export of chronological execution steps (`index,kind,actor,actorAddress,target,targetAddress,functionName,valueWei,gasUsed,success,summary`). |
| 10 | `evidence/patterns.json` | `evidence` | JSON (`2-space indented`) | Full array of `PatternMatch` records produced by `runDetectors()`, together with `nodesCount` and `flatNodesCount` from `parseForgeTrace()`. Proves which heuristic rules fired and which exact `stepIndex` / `traceLine` / `slot` evidence items triggered them. |
| 11 | `evidence/gas-flame.json` | `evidence` | JSON (`2-space indented`) | Array of `GasFlameEntry` objects (`id`, `label`, `depth`, `gas`, `share`) computed by `buildFlame()`. Proves proportional gas consumption across call frames. |
| 12 | `chain-of-custody.json` | `custody` | JSON (`2-space indented`) | Cryptographic manifest listing execution provenance (`engine`, `caseId`, `source`, `generatedAt`, `command`, `foundryInvocation`, `versions` for `forge`/`solc`/`node`/`os`) and the SHA-256 digest and byte size of every file in `report/` and `evidence/`. |

## 2. `chain-of-custody.json` Schema

```json
{
  "schema": "w3-forensics.chain-of-custody/v1",
  "caseId": "lab-reentrancy",
  "scenarioId": "reentrancy",
  "title": "Classic Checks-Effects-Interactions Reentrancy",
  "generatedAt": "2026-04-20T00:00:00.000Z",
  "source": "foundry-live",
  "command": "forge test --match-contract ForensicsHarnessTest --match-test test_reentrancy -vvvv",
  "foundryInvocation": "forge test --match-contract ForensicsHarnessTest --match-test test_reentrancy --json -vvv",
  "versions": {
    "engine": "0.2.0",
    "node": "v22.14.0",
    "os": "win32 10.0.26100 (x64)",
    "forge": "forge Version: 1.0.0-stable",
    "solc": "0.8.24"
  },
  "reportSha256": "87cf3fa582bb565bf4488df747f4d182cf67e4f8ae5cc1bc94435ce610297555",
  "files": [
    {
      "path": "report/report.md",
      "bytes": 4621,
      "sha256": "..."
    },
    {
      "path": "report/report.json",
      "bytes": 15420,
      "sha256": "..."
    }
  ],
  "notes": [
    "Every file listed under `files` was produced in a single deterministic pass from the simulation artifact and raw trace.",
    "Verify any entry with: `sha256sum <path>` (or `Get-FileHash -Algorithm SHA256 <path>` on Windows) and compare against the recorded digest.",
    "If `source` is `deterministic-fallback`, Foundry (`forge`) was not reachable on PATH when the bundle was built; re-run with Foundry installed to obtain a live EVM trace."
  ]
}
```

### Sequential SHA-256 Chain of Custody (`/api/evidence/[caseId]/manifest`)

In addition to per-file SHA-256 digests, the Evidence Workbench (`/evidence`) and `GET /api/evidence/[caseId]/manifest` compute a sequential hash chain across all 12 files in archive order:

$$H_0 = \text{SHA256}(\text{"0000...0000"} \mathbin{\Vert} \text{":"} \mathbin{\Vert} \text{path}_0 \mathbin{\Vert} \text{":"} \mathbin{\Vert} \text{sha256}(\text{file}_0))$$

$$H_i = \text{SHA256}(H_{i-1} \mathbin{\Vert} \text{":"} \mathbin{\Vert} \text{path}_i \mathbin{\Vert} \text{":"} \mathbin{\Vert} \text{sha256}(\text{file}_i))$$

The final link $H_{n-1}$ is reported as `rootChainHash`. Modifying even a single byte in any CSV, JSON, Markdown, or trace file invalidates its leaf `sha256` and every subsequent `chainHash` link through `rootChainHash`.

## 3. How to Verify a Bundle Independently

### Option A — PowerShell (Windows)

```powershell
# 1. Extract the downloaded forensic bundle
Expand-Archive -Path .\lab-reentrancy-forensic-bundle.zip -DestinationPath .\bundle-verify -Force
Set-Location .\bundle-verify

# 2. Parse chain-of-custody.json and verify every recorded SHA-256 digest
$custody = Get-Content .\chain-of-custody.json -Raw | ConvertFrom-Json
$failures = 0

foreach ($entry in $custody.files) {
  $actualHash = (Get-FileHash -Algorithm SHA256 -Path $entry.path).Hash.ToLower()
  $actualBytes = (Get-Item $entry.path).Length
  if ($actualHash -ne $entry.sha256 -or $actualBytes -ne $entry.bytes) {
    Write-Error "MISMATCH: $($entry.path) expected=$($entry.sha256) ($($entry.bytes)B) actual=$actualHash ($($actualBytes)B)"
    $failures++
  } else {
    Write-Host "OK  $($entry.sha256)  $($entry.bytes)B  $($entry.path)"
  }
}

if ($failures -eq 0) {
  Write-Host "`nALL $($custody.files.Count) EVIDENCE FILES VERIFIED." -ForegroundColor Green
}
```

### Option B — POSIX Shell (`jq` + `sha256sum` / `shasum`)

```bash
unzip -q lab-reentrancy-forensic-bundle.zip -d bundle-verify
cd bundle-verify

jq -r '.files[] | "\(.sha256)  \(.path)"' chain-of-custody.json | sha256sum -c -
```

Expected output:

```text
report/report.md: OK
report/report.json: OK
evidence/artifact.json: OK
evidence/trace.txt: OK
evidence/foundry-stdout.txt: OK
evidence/foundry-stderr.txt: OK
evidence/storage-diff.csv: OK
evidence/balance-timeline.csv: OK
evidence/timeline.csv: OK
evidence/patterns.json: OK
evidence/gas-flame.json: OK
```

## 4. Generating or Downloading a Bundle

1. **Via the Web UI (`/evidence`)**:
   Open `http://localhost:3000/evidence`, select any case in the case bar, and click **Download forensic bundle (.zip)**. This hits `GET /api/bundle/<caseId>` and streams `<caseId>-forensic-bundle.zip`.

2. **Via HTTP (`curl` / `Invoke-WebRequest`)**:
   ```powershell
   Invoke-WebRequest http://localhost:3000/api/bundle/reentrancy -OutFile reentrancy-forensic-bundle.zip
   ```

3. **Via the CLI**:
   ```powershell
   npm run forensics -- bundle --scenario reentrancy --out artifacts/bundles/lab-reentrancy-forensic-bundle.zip
   ```
