### 2. `/trace` — "How we trace" (the animated explainer)
A page that teaches the tracing pipeline, with **working animation**:
  Stage 1 — RAW: a real `forge -vvvv` excerpt streams in (use REAL trace text from the reentrancy
    artifact, fetched from the API; if the artifact is missing, fall back to `/api/scenarios`+simulate
    — but never invent trace text).
  Stage 2 — PARSE: show how the parser assigns DEPTH. Forge indents 4 columns per level, so
    `depth = floor(branchIndex / 4)`. Animate the indentation being measured and the depth badge
    appearing on each node. Show the real code lines from `trace-parser.ts` (short excerpts) next to
    the visual.
  Stage 3 — TREE: the call tree materialising, parent → child, with the nested `withdraw()` calls
    visible.
  Stage 4 — DETECT: the detector rules firing on the nodes they match (e.g. Reentrancy matches
    repeated target address at depth N and N+2). Use the real detector names and the real
    `DETECTOR_CATALOG` `looksFor` text.
  Stage 5 — REPORT: the finding becoming a report section and a bundle entry.
- The animation must be one coherent, authored moment — a scripted timeline with a `draw(t)`-style
  pure function, seeded randomness only where needed, and it must respect
  `prefers-reduced-motion` (kill all animation; show the finished state). The rules are in
  `docs/design/RED-ROOM.md` §motion and in `.claude/skills/motion-graphics/SKILL.md` — READ THE
  MOTION-GRAPHICS SKILL and follow it (pure `draw(t)`, `document.fonts.ready` before measuring, 5%

- Do NOT rebuild the existing `AttackReplay` canvas piece (another agent owns it). Your animation is
  the trace-pipeline explainer. Make it clearly different in form: a staged, scroll-driven
