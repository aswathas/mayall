# WHAT TO BUILD

## app/page.tsx — THE OVERVIEW
This is the first screen a judge sees. It must look like an instrument, not a
SaaS template.

Structure (top to bottom):
1. **Page head.** A real `<h1>` with the page's purpose in words — e.g.
   "Exploit landscape". NO kicker/eyebrow above it (banned). Beside it, a
   short sentence of orientation (max 75ch). On the right, two actions:
   "Registry" (ghost) and "Live lab" (primary).
2. **MetricStrip** (from components/MetricStrip.tsx) — ONE band with the five
   headline numbers: tracked loss, incidents, reproducible cases, chains
   covered, distinct attack vectors. Do NOT use StatCard or a card grid.
   Values are strings you format (e.g. `$2.39B`).
3. **Two-column instrument row.** Left (2/3): the loss timeline chart. Right
   (1/3): the live-engine panel.
   - LossTimelineChart: monthly loss as an area chart (recharts). Use a subtle
     arterial gradient fill (this is data, so colour is allowed — but no
     decorative gradients elsewhere). Axis labels in the mono face, ink-dim.
     Tooltip shows the month and the exact loss.
   - EngineStatus: reads /api/status. Shows the Foundry state as a word
     ("Engine online" / "Foundry not installed") plus the scenario and
     artifact counts. A live dot (mint) when online. If Foundry is missing,
     give the recovery: "Run npm run setup:foundry". This panel must be
     compact — it is a status readout, not a marketing block.
4. **Attack vector breakdown + chain distribution.** VectorBreakdown renders
   `byVector` as a ranked list: the vector label, its count and its share of
   total loss, with a proportional bar. Vector chips carry the severity
   weighting. ChainDonut renders `byChain` as a donut with CHAIN_COLORS and a
   legend that shows the loss per chain.
5. **Severity split + top incidents.** SeveritySplit renders `severity` as a
   single stacked bar with a text legend (never colour alone). The top-incidents
   table (IncidentTable) lists name, target, chain, severity chip, loss, date
   and a "REPRO" badge when `incident.reproducible` — linking to
   `/cases/<slug>`.
6. **A closing line that is honest.** State that the incidents are public
   disclosures and that the reproductions are local Foundry simulations. No
   marketing claims.

The page must fill its space properly: no large empty regions, no section
pushed to one side, equal margins. Use a 12-column grid with explicit spans.
