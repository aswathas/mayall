# WHAT THE API GIVES YOU
GET  /api/scenarios -> ScenarioSpec[]  (id, title, vectorId, chain, description, lookFor[], contractName, testFile)
POST /api/simulate  { scenarioId } -> SimulationResult
POST /api/simulate/all -> { results: SimulationResult[], totalMs }
GET  /api/report/<caseId>?scenario=<scenarioId> -> ForensicReport
POST /api/report/<caseId>/narrative { text } -> { ok, path }
GET  /api/bundle/<caseId>?scenario=<scenarioId> -> zip download
GET  /api/incidents/<slug> -> { incident }
GET  /api/status -> { foundry, scenarios, artifacts, version }

## 1. app/lab/page.tsx — THE LIVE LAB (the demo stage)
This is the screen the judges watch. It must feel like an instrument you can
fire, not a settings page.
- A page head with a real <h1> ("Live lab" or similar). No kicker above it.
- **Scenario library**: the 6 scenarios from /api/scenarios as a selectable
  list. Each entry shows: title, vector chip, chain chip, the contract name,

  marketing.

  result list: pass/fail, duration, loss, and a link into the results area.
  While it runs, a live status line with an elapsed timer and a live dot.

  `<LiveSimPanel>`.
- **Results area**: LiveSimPanel renders the AttackReplay canvas piece, the
  trace, the gas flame, the storage diff, the balances, the pattern findings
  and the raw forge output.
- **Forensic report + bundle**: a button that GETs
  `/api/report/lab-<scenarioId>?scenario=<scenarioId>` and shows the report
  inline (ReportView), plus a download button for
  `/api/bundle/lab-<scenarioId>?scenario=<scenarioId>`.
- Be honest in the copy: this is a local Foundry simulation on a local EVM,
  not mainnet. Say so once, clearly, near the top of the page.
