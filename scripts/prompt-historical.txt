## WHAT TO BUILD

### 1. `packages/forensic-engine/src/historical.ts` — analysis over the real registry
For each of the 16 incidents in `packages/core/src/incidents.ts`:
- Run our **own detector suite** in "historical mode": there is no local trace for a historical
  incident, so the analysis must work from the incident's recorded evidence (chain, date, loss,
  attack vectors, target, actors, tx references, the narrative of what happened).
- For each incident, produce a `HistoricalFinding[]`:
  - `vector` (our 16-vector taxonomy id), `confidence` (0..1), `biblePattern` (the matching attack
    name from Bible sheet `04 Attack Pattern Catalog` — e.g. "Classic Reentrancy", "Classic Flash
    Loan Exploit", "Read-Only Reentrancy"), `bibleSignals` (the signal names from sheet
    `03 Detection Signals` that WOULD prove it — mark each as `expected` / `observed` /
    `notApplicable`; `observed` only if the incident's recorded evidence actually contains it),
    `evidenceRefs` (the incident's tx/reference ids), `reproduction` (link to the scenario id when
    we have a live local reproduction of that vector — `packages/core/src/incidents.ts` has a
    `scenarioId`/`reproducible` field; use it), and `limitations` (quote the detector's `limitation`
    text from `DETECTOR_CATALOG`).
- Aggregate into: findings by vector, findings by Bible family, confidence distribution, and a
  coverage summary (how many of the 16 incidents we can locally reproduce = the "reproducible" count).
- BE HONEST: this is metadata-driven retrospective classification, NOT a mainnet trace analysis.
  Every panel that shows it must say so.
