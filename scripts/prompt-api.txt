# ROUTES TO IMPLEMENT (Next.js App Router route handlers)

1. `app/api/status/route.ts` — GET
   -> { foundry: boolean, scenarios: number, artifacts: number, version: string }
   foundry = foundryAvailable() from the engine; scenarios = SCENARIOS.length; artifacts = count of *.json files in artifactsDir(); version = '0.1.0'.

2. `app/api/overview/route.ts` — GET
   -> {
        totals: { incidents, lossUsd, reproducible, chains, vectors },
        byVector:  { id: AttackVectorId, label, count, lossUsd }[],
        byChain:   { chain: Chain, count, lossUsd }[],
        timeline:  { month: 'YYYY-MM', lossUsd, count }[],
        severity:  { severity: Severity, count }[],
        topIncidents: Incident[]   // top 6 by lossUsd desc
     }
   Compute from INCIDENTS. `byVector` counts an incident once per distinct vector it carries, and sums its lossUsd into each vector's total. `timeline` is grouped by incident date month, sorted ascending. `severity` maps each incident to a severity derived from lossUsd (>=100M -> critical, >=10M -> high, >=1M -> medium, else low) — document that rule in a comment. `chains` = distinct chain count, `vectors` = distinct vector count, `reproducible` = count of incident.reproduitable.

3. `app/api/incidents/route.ts` — GET -> Incident[] (newest first by date desc).

4. `app/api/incidents/[slug]/route.ts` — GET -> { incident: Incident | null }. In Next 15 the route handler context params is a Promise: `export async function GET(req: Request, { params }: { params: Promise<{ slug: string }> })` — await it. Return 404 with `{ incident: null }` when not found.

5. `app/api/scenarios/route.ts` — GET -> ScenarioSpec[]

6. `app/api/simulate/route.ts` — POST
   body: { scenarioId: string }
   -> SimulationResult (the full object from runSimulation)
   Set `export const maxDuration = 300;` and `export const dynamic = 'force-dynamic';`.
   Validate the scenarioId against SCENARIO_BY_ID; if unknown, return 400 with { error: 'Unknown scenario' }.

7. `app/api/simulate/all/route.ts` — POST -> { results: SimulationResult[], totalMs: number } using runAllSimulations(). maxDuration = 600, dynamic force-dynamic.

8. `app/api/report/[caseId]/route.ts` — GET
   Query param `scenario` (optional). Resolve the incident via INCIDENT_BY_SLUG.get(caseId). If a `scenario` query param is given, run a simulation for it (reuse the artifact on disk if the scenario has not changed — you may simply call runSimulation, it is fast enough; but to avoid re-running forge on every page load, first check whether artifacts/<scenario>.json exists and reuse it by constructing the SimulationResult from the artifact — implement a small helper `resultFromArtifact(scenarioId, artifact)` OR just call runSimulation and accept the cost. Prefer: try to reuse; if you cannot reuse cleanly, call runSimulation.)
   -> ForensicReport built with buildReport(caseId, sim, incident ?? null)
   caseId semantics: for an incident use the incident slug; for a lab scenario use `lab-<scenarioId>` (incident lookup returns null, which is fine — buildReport handles a null incident).

9. `app/api/report/[caseId]/narrative/route.ts` — POST
   body: { text: string } -> { ok: true, path: string }
   Calls saveNarrative(caseId, text) from the engine. This is how MiniMax Code injects a hand-authored executive summary into the generated report. Validate that text is a non-empty string; 400 otherwise.

10. `app/api/bundle/[caseId]/route.ts` — GET
    Query param `scenario` (optional, same resolution as the report route).
    Build the ForensicReport, then call buildForensicBundle(report, sim) -> { filename, buffer }.
    Respond with the zip: headers { 'Content-Type': 'application/zip', 'Content-Disposition': `attachment; filename="${filename}"`, 'Content-Length': String(buffer.length) } and body = buffer (a Node Buffer is acceptable as a Response body).

11. `app/api/report/[caseId]/markdown/route.ts` — GET (nice-to-have, low cost)
    -> text/markdown of reportToMarkdown(report) with Content-Disposition attachment.
