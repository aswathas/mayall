## 1. oracle-manipulation
Files: src/NaivePriceOracle.sol, src/OracleLendingPool.sol, test/OracleExploit.t.sol
- `NaivePriceOracle`: holds a "quote reserve" that ANY address can push with no access control.
  ```
  contract NaivePriceOracle {
      uint256 public constant BASE_UNITS = 100;
      uint256 public quoteReserve;             // manipulable
      uint256 public pushedAt;
      function push(uint256 newQuote) external { quoteReserve = newQuote; pushedAt = block.timestamp; }
      function price() public view returns (uint256) { return quoteReserve == 0 ? 1e18 : (quoteReserve * 1e18) / BASE_UNITS; }
  }
  ```
- `OracleLendingPool`: lenders deposit ETH. Collateral is valued in base units: a depositor's collateral is worth `(collateralWei / 1e18) * price()`. LTV = 50%.
  ```
  contract OracleLendingPool {
      NaivePriceOracle public immutable oracle;
      mapping(address => uint256) public collateral;   // wei deposited
      mapping(address => uint256) public debt;
      uint256 public constant LTV_BPS = 5000;          // 50%
      function deposit() external payable { collateral[msg.sender] += msg.value; }
      function maxBorrow(address who) public view returns (uint256) {
          uint256 units = collateral[who] / 1e18;
          return (units * oracle.price() * LTV_BPS) / 10000;
      }
      function borrow(uint256 amount) external {
          require(amount <= maxBorrow(msg.sender), "exceeds ltv");
          debt[msg.sender] += amount;
          (bool ok,) = msg.sender.call{value: amount}(""); require(ok, "transfer failed");
      }
  }
  ```
- Attack test: victim deposits 1000 ETH into the pool. Attacker deposits 10 ETH, then calls `oracle.push(...)` so that `price()` returns a high value (e.g. push 1000 ether -> price = 1000e18*1e18/100 = 10e18, i.e. 10 ETH per base unit) and then `borrow()`s far more than the 10 ETH deposited. With 10 ETH collateral = 10 units * 10 ETH * 0.5 = 50 ETH max borrow. The pool holds 1000 ETH so the borrow succeeds. The attacker walks away with 50 ETH minus its 10 ETH deposit.
  - lossWei = 50 ETH (the amount drained from the pool beyond the attacker's own deposit) — measure `poolBefore - poolAfter` and subtract the attacker's deposit, and assert it is > 0.
  - The storage diff must include the oracle's `quoteReserve` slot changing from 0 to the pushed value, and the pool's `debt` mapping entry for the attacker changing from 0 to 50 ETH.

## 3. flash-loan
Files: src/FlashLoanPool.sol, src/SpotOracle.sol, src/CollateralVault.sol, test/FlashLoanExploit.t.sol
- `FlashLoanPool`: 1000 ETH of liquidity, a 10 bps fee, and `flashLoan(uint256 amount, address borrower)` that sends ETH out and requires the principal + fee back in the same transaction.
  ```
  contract FlashLoanPool {
      uint256 public constant FEE_BPS = 10;
      uint256 public liquidity;
      function addLiquidity() external payable { liquidity += msg.value; }
      function flashLoan(uint256 amount, address borrower) external {
          require(amount <= liquidity, "insufficient liquidity");
          uint256 fee = (amount * FEE_BPS) / 10000;
          liquidity -= amount;
          (bool ok,) = borrower.call{gas: 900000, value: amount}(""); require(ok, "loan failed");
          require(address(this).balance >= amount + fee, "not repaid");
          liquidity += amount + fee;
      }
  }
  ```
- `SpotOracle`: a quote bond that moves the price. The bond is posted as ETH and can be unwound by the same depositor IMMEDIATELY (no unbonding delay) — that is the vulnerability.
  ```
  contract SpotOracle {
      uint256 public constant BASE_UNITS = 100;
      mapping(address => uint256) public bonds;
      uint256 public totalBond;
      function push() external payable { require(msg.value > 0, "no bond"); bonds[msg.sender] += msg.value; totalBond += msg.value; }
      function unwind() external {
          uint256 amt = bonds[msg.sender];
          bonds[msg.sender] = 0; totalBond -= amt;
          (bool ok,) = msg.sender.call{value: amt}(""); require(ok, "unwind failed");
      }
      function price() public view returns (uint256) { return totalBond == 0 ? 1e18 : (totalBond * 1e18) / BASE_UNITS; }
  }
  ```
- `CollateralVault`: holds 1000 ETH of lender deposits; collateral valued the same way as the oracle scenario; LTV 50%; `borrow()` pays out ETH.
- Attack test (the classic flash-loan price inflation, capital-free):
  1. Pool has 1000 ETH liquidity. Vault has 1000 ETH of lender deposits.
  2. The attacker contract takes a 900 ETH flash loan from the pool and, inside the callback, calls `oracle.push{value: 900 ether}()` — the oracle's totalBond becomes 900 ETH, so `price()` becomes 9 ETH per base unit (900e18*1e18/100 = 9e18).
  3. The attacker deposits 100 ETH of collateral into the vault. 100 ETH = 100 units * 9 ETH * 0.5 = 450 ETH max borrow.
  4. The attacker borrows 450 ETH from the vault (the vault holds 1000 ETH so it pays out).
  5. The attacker calls `oracle.unwind()` to get the 900 ETH bond back, then repays the flash loan (900 ETH + 0.1% fee = 900.9 ETH). The attacker ends up with the 450 ETH it borrowed, minus the 0.9 ETH fee, and its 100 ETH collateral is still locked in the vault.
  6. lossWei = the vault's ETH loss that is NOT covered by the attacker's own collateral = `vaultBefore - vaultAfter - 100 ether` (the attacker's collateral stays in the vault). Assert it is > 0.
  - The diff must include the oracle's `totalBond` slot going 0 -> 900 ETH and the vault's `debt` entry for the attacker going 0 -> 450 ETH.
  - IMPORTANT: the flash loan callback gives the attacker contract 900 ETH, which it must forward as the oracle bond; use a callback pattern (`receive()` or an explicit `onFlashLoan()` the pool calls). The pool calls `borrower.call{gas: 900000, value: amount}` so implement `receive() external payable` on the attacker and branch on a state variable.

## 4. delegatecall

- `DelegateVault` forwards arbitrary calldata to a CALLER-SUPPLIED implementation via delegatecall, with no allowlist — that is the bug:
  ```

      address public owner;
      mapping(address => uint256) public balances;
      function deposit() external payable { balances[msg.sender] += msg.value; }
      function execute(address implementation, bytes calldata data) external {
          (bool ok,) = implementation.delegatecall(data); require(ok, "delegatecall failed");
      }
      function withdraw() external { uint256 b = balances[msg.sender]; balances[msg.sender] = 0; (bool ok,) = msg.sender.call{value: b}(""); require(ok); }
  }
  ```
- `MaliciousImplementation` MUST declare the SAME storage layout as DelegateVault (owner at slot 0, balances at slot 1) so that, under delegatecall, it can read and write the vault's storage:
  ```
  contract MaliciousImplementation {
      address public owner;                 // slot 0
      mapping(address => uint256) public balances;  // slot 1
      function drain(address payable to) external {
          uint256 amount = address(this).balance;
          balances[to] += amount;           // writes the VAULT's storage
          (bool ok,) = to.call{value: amount}(""); require(ok, "drain failed");
      }
  }
  ```
  (under delegatecall, `address(this)` is the vault, so the balance moved is the vault's ETH).
- Attack test: victim deposits 50 ETH. The attacker deploys MaliciousImplementation and calls `vault.execute(address(impl), abi.encodeCall(MaliciousImplementation.drain, (payable(attacker))))`. The vault's 50 ETH is force-sent to the attacker and the vault's `balances` accounting is corrupted.
